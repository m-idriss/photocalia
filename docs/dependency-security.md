# Dependency audit remediation

The former audit job parsed modern, pretty-printed npm JSON line by line and could report success despite high-severity findings. The replacement validates the complete npm audit v2 inventory and severity totals, fails on malformed/unavailable/inconsistent reports, and rejects any high or critical finding. The job audits the lockfile without installing packages or running lifecycle scripts. Actions are pinned, checkout credentials are not persisted, permissions are read-only, and execution is capped at five minutes.

On October 28, 2026, the original lockfile audit reported 63 affected dependencies (61 high, two moderate). These are package counts, not 63 distinct advisories or evidence of production exploitation. Refreshing within existing declared dependency ranges reduced that to 14 affected packages (12 high). Exact same-major overrides then updated fast-uri to 3.1.9, undici to 7.30.1, qs to 6.16.1, Vite to 8.3.3, gRPC JS to 1.14.5 and the Vercel CLI configuration's Zod 4 dependency to 4.6.6. The final local lockfile audit reported zero findings at that observation time.

No forced npm audit fix, declared direct dependency major upgrade, product source change, backend change, payment/price change or real provider request is included. The lockfile refresh updates direct/transitive versions already permitted by the manifest. Overrides intentionally take precedence over upstream pins, including Firebase's gRPC dependency and Angular's build-time Vite dependency; retain them only while required and verify compatibility in CI. Synthetic UI tests do not validate a real Firebase session or every production provider path.

Validation must include the audit-parser regression cases, lockfile audit, existing lint/unit/build/contract checks, and all ten synthetic QA journeys. A clean audit is a point-in-time registry result, not a guarantee that no vulnerability exists. Existing dependency-update automation should propose future updates through PRs; no automatic merge is activated here.

The audit workflow is also reusable from Frontend CI. The already-required `Lint, test, and build` job depends on both synthetic QA and the dependency-security job, uses `always()`, and explicitly requires both results to be `success`. Failures, cancellations, skipped jobs or missing success cannot silently skip the required frontend check. Existing active branch rules therefore make both QA and security blocking without adding an administration permission or weakening the upstream-contract gate.
